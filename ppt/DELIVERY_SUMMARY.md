```
"Currently, when a device crashes, someone has to:
- Log into the stack trace portal
- Extract the crash data
- Search through thousands of lines of source code

- This involves multiple developers and can take hours or days

The impact is significant: delayed features, reduced productivity,
higher costs, and unhappy customers waiting for fixes."
```

### Solution (Slide 3, 3 min):
```

- Takes a stack trace as input
- Uses AI to analyze the code automatically
- Identifies the root cause with confidence levels
- Provides specific debugging steps
- Suggests fixes based on actual source code

The results: 60 seconds from crash to suggestion. 90% time savings.
Zero manual code searching."
```

### Architecture (Slide 4, 3 min):
```
"Here's how it works technically:
1. Start with crash data from the RDK portal
2. Our Chrome extension captures it
3. AI engine (Gemini/GPT/Claude) analyzes
4. GitHub integration fetches source code context
5. AI generates root cause summary and fix suggestions

We support multiple AI providers, GitHub integration, and have
features like JSON upload and interactive Q&A."
```

## 💡 Answers to Expected Questions

**Q: Which AI models does it support?**
A: "We support Gemini 2.5 (Google), GPT-5-2 (Azure), and Claude 4.6 Sonnet (AWS). Users can choose their preferred provider in settings."

**Q: How accurate is it?**
A: "For common patterns like null pointers and memory corruption, it's highly accurate with 85-90% confidence. It also provides multiple hypotheses ranked by likelihood, so developers can investigate alternatives."

**Q: How long does it take?**
A: "Typically 10-15 seconds for analysis, up to 60 seconds for complex traces. Compared to 2-4 hours manually, it's a 95%+ time reduction."

**Q: What languages does it support?**
A: "It works with any language - C/C++, Java, Python, JavaScript, etc. The AI understands stack trace formats from multiple platforms."

**Q: When can we start using it?**
A: "It's ready now! We can begin a phased rollout starting next sprint. Initial rollout to your team, then expand based on feedback."

**Q: What about cost?**
A: "We support both free tier (Google Gemini) and organization-provided APIs. For OpenAI, we use your existing enterprise agreement, so no additional licensing needed."

**Q: What if the GitHub repo is private?**
A: "The extension uses personal access tokens with read-only permissions. It only fetches files mentioned in the stack trace, and all data stays within your organization's infrastructure."

**Q: Can it handle minidumps?**
A: "Currently it works with stack traces extracted from minidumps. We can extend it to parse minidumps directly in Phase 2."
